## 1. Project Overview

This project implements a complete IEEE 802.11a OFDM physical-layer transceiver on a Xilinx Zynq-7020 SoC. The system has four main components that work together:

| Component | Description |
|-----------|-------------|
| **HDL (FPGA logic)** | OFDM TX/RX IP cores, AWGN channel emulator, IQ capture BRAMs — all in the Zynq PL |
| **NO-OS Firmware** | Bare-metal C running on the ARM Cortex-A9 PS — configures AD9361 via SPI, drives GPIO control bus |
| **AD9361 RF Front-End** | Up/down-converts baseband IQ to 2.4 GHz RF via LVDS interface to the PL |
| **Python GUI** | Real-time BER curves, IQ constellations, FFT spectrum, and packet hex viewer over UART |

**Typical loopback test flow:**

```
ARM PS  →(gpio_o)→  OFDM TX  →  [AWGN]  →  OFDM RX  →(gpio_i)→  ARM PS  →(UART)→  GUI
                         ↕ LVDS ↕                  ↕ LVDS ↕
                       AD9361 DAC               AD9361 ADC
                              ↕ RF cable (SMA loopback) ↕
```

## 3. Hardware Requirements

| Item | Part Number / Details |
|------|-----------------------|
| Development board | **ZedBoard** (Avnet) — Xilinx Zynq-7020 clg484-1 |
| RF daughter card | **FMCOMMS3** (Analog Devices) — AD9361 transceiver |
| RF loopback cable | SMA male-to-male coaxial cable (TX SMA → RX SMA on FMCOMMS3) |
| USB cable (UART) | Micro-USB to USB-A — connects to the ZedBoard **UART** port (J14) |
| USB cable (JTAG) | Same or separate micro-USB — connects to **PROG/JTAG** port (J23) |
| SD card | micro-SD, any size — used to boot the FSBL + bitstream + firmware |
| Power supply | 12 V / 3 A DC jack for ZedBoard |
| Host PC | Linux or Windows with Vivado and Vitis installed |

### Physical Setup

1. Mount the FMCOMMS3 card onto the ZedBoard **FMC-LPC** connector (J5). Press firmly until the connector seats fully.
2. Connect the **SMA loopback cable** between the TX port and the RX port on FMCOMMS3.
3. Set the ZedBoard **JP7 boot mode jumpers** to SD card boot: `[MIO2=GND, MIO3=3V3, MIO4=3V3, MIO5=GND, MIO6=GND]` (see ZedBoard HW User Guide, Table 2).
4. Connect the **UART micro-USB** cable to J14 (the one labelled "UART").
5. Connect the **JTAG micro-USB** cable to J23 (labelled "PROG") — needed only for programming.

## 4. Software Prerequisites

### 4.1 Xilinx Tools

| Tool | Version | Purpose |
|------|---------|---------|
| **Vivado** | 2022.2 | Synthesise and implement the FPGA bitstream |
| **Vitis IDE** (or Vitis Classic) | 2022.2 | Build the bare-metal C firmware |
| **arm-none-eabi-gcc** | bundled with Vitis | Compiles `main.c` for Cortex-A9 |

Vivado and Vitis are part of the Xilinx Unified Installer. The free **Vivado WebPACK** licence covers the Zynq-7020 device used here.

> **Windows note:** `build.tcl` patches a Vivado 2022.2 Windows simulator wrapper bug. On Linux this is not needed but the patch is harmless.

### 4.2 Python GUI Dependencies

Python 3.8 or later is required. Install dependencies with:

```bash
pip install pyserial matplotlib numpy Pillow
```

| Package | Purpose |
|---------|---------|
| `pyserial` | UART communication with ZedBoard |
| `matplotlib` | BER plots, IQ constellation, FFT spectrum |
| `numpy` | FFT computation and signal processing |
| `Pillow` | Required by matplotlib's TkAgg backend |

Verify the installation:

```bash
python3 -c "import serial, matplotlib, numpy, PIL; print('All OK')"
```

### 4.3 Analog Devices HDL Library

The Vivado block design (`system_bd.tcl`) instantiates ADI IP cores (`axi_ad9361`, `axi_clkgen`, `util_pack`). These must be pre-built before running `build.tcl`.

The ADI HDL library is already included in this repository under:
```
open_ofdm_phy-hw-clean-ofdm-rebuild/adi-hdl/
```

If it is **missing** (e.g., after a fresh clone that did not initialise submodules), fetch it:

```bash
git submodule update --init --recursive
```

Or clone it manually:

```bash
cd open_ofdm_phy-hw-clean-ofdm-rebuild/
git clone https://github.com/analogdevicesinc/hdl.git adi-hdl
cd adi-hdl
git checkout hdl_2022_r2      # match your Vivado version
```

## 5. One-Time Setup: Build the ADI HDL Libraries

> **Do this once.** After the ADI IP cores are packaged you never need to repeat this step unless you change the `adi-hdl` branch.

Open a terminal with Vivado on the PATH, then:

```bash
cd open_ofdm_phy-hw-clean-ofdm-rebuild/
vivado -mode batch -source build_adi_lib.tcl
```

This script packages `axi_ad9361`, `axi_clkgen`, `util_pack`, and other ADI cores into Vivado IP format. It takes 5–15 minutes. When complete you will see:

```
==== ADI library build complete ====
```

If you see errors like `IP not found: axi_ad9361`, the `adi-hdl/` directory is missing or incomplete — see Section 4.3.

## 6. Step 1: Build the FPGA Bitstream (Vivado)

```bash
cd open_ofdm_phy-hw-clean-ofdm-rebuild/v2/boards/zed_fmcs3/
vivado -mode batch -source build.tcl 2>&1 | tee build.log
```

**What this does:**

1. Deletes any previous `stage1c/` build directory.
2. Creates a Vivado project targeting `xc7z020clg484-1`.
3. Points the IP catalogue at `adi-hdl/library/`.
4. Runs `system_bd.tcl` to generate the block design (Zynq PS + axi_ad9361 + AXI GPIO + axi_clkgen).
5. Adds all RTL sources: `system_top.v`, `awgn_noise_gen.v`, `iq_sample_fifo.v`, `tx_packet_rom_mcs.v`, and all openofdm_tx / openofdm_rx Verilog files.
6. Runs synthesis (12 parallel jobs).
7. Inserts an ILA debug core (10 probes — TX IQ, RX byte, FCS status, etc.).
8. Runs implementation and bitstream generation.
9. Exports the hardware platform as `stage1c/stage1c.xsa`.

**Expected outputs:**

```
stage1c/stage1c.runs/impl_1/system_top.bit   ← bitstream
stage1c/stage1c.xsa                          ← hardware platform for Vitis
```

**Build time:** ~30–60 minutes depending on host CPU.

**Checking the build succeeded:**

```bash
grep "write_bitstream.*Completed" build.log
# Should print: INFO: [Vivado 12-1842] Finished write_bitstream ...
```

Also look for the BRAM inference confirmation:

```bash
grep -i "Inferred RAM" build.log | grep "block=YES"
# Should show tx_iq_cap_i, tx_iq_cap_q, rx_iq_cap_i, rx_iq_cap_q as block RAM
```

If you see `block=NO` for the IQ capture arrays, the block RAM inference failed and the design will still work but the 4096-sample capture may not fit.

## 7. Step 2: Create the Vitis Platform and Build Firmware

### 7.1 Create / Update the Hardware Platform in Vitis

> If you already have the `stage3_mcs_platform` in Vitis from a previous build and only rebuilt the bitstream, you just need to update the XSA — right-click the platform project → **Update Hardware Specification** → point to the new `stage1c.xsa`.

For a **fresh** Vitis setup:

1. Open **Vitis IDE** (2022.2).
2. Set the workspace to `OFDMPROJECTCURRENT/` (the root of this repo).
3. **File → New → Platform Project**
   - Platform name: `stage3_mcs_platform`
   - Hardware (XSA): browse to `open_ofdm_phy-hw-clean-ofdm-rebuild/v2/boards/zed_fmcs3/stage1c/stage1c.xsa`
   - OS: **standalone**, CPU: **ps7_cortexa9_0**
4. Build the platform: right-click → **Build Project**.

### 7.2 Import and Build the Firmware Application

1. **File → New → Application Project**
   - Platform: select `stage3_mcs_platform`
   - Application name: `stage3_mcs_app1`
   - Template: **Empty Application (C)**
2. In the **Explorer**, right-click `stage3_mcs_app1/src` → **Import Sources** → select all files from `stage3_mcs_app1/src/` in this repo (`main.c`, `app_config.h`, `parameters.h`).
3. Right-click the application → **Build Project**.

**Or build from the command line** if the Makefile is already configured:

```bash
cd stage3_mcs_app1/Debug/
make all
```

The compiled ELF will be at: `stage3_mcs_app1/Debug/stage3_mcs_app1.elf`

## 8. Step 3: Program the ZedBoard

You have two options:

### Option A — JTAG (fastest for development)

With the JTAG cable connected:

1. In Vitis: **Xilinx → Program Device** → select `system_top.bit` → **Program**.
2. Then **Run → Run As → Launch on Hardware (Single Application Debug)** to load the ELF.
3. Open a serial terminal (e.g. PuTTY or `minicom`) at **115200 baud, 8N1** on the ZedBoard UART port.

### Option B — SD Card (standalone, no PC needed after programming)

Use Vitis to create a boot image:

1. **Xilinx → Create Boot Image**
2. Add partitions in this order:
   - `stage3_mcs_platform/zynq_fsbl/fsbl.elf` — type: **bootloader**
   - `stage1c/stage1c.runs/impl_1/system_top.bit` — type: **datafile**
   - `stage3_mcs_app1/Debug/stage3_mcs_app1.elf` — type: **datafile**
3. Output: `BOOT.BIN`
4. Copy `BOOT.BIN` to the root of a FAT32-formatted SD card.
5. Insert the SD card, power on — the ZedBoard will boot automatically.

### Verifying Boot

Open a serial terminal at **115200 baud**. You should see:

```
AD9361 init OK
Calibration complete
OFDM system ready. Type HELP for commands.
>
```

If you see nothing, check: correct COM port, 115200 baud, boot mode jumpers set to SD.

## 10. Using the System — CLI Commands

Commands can be typed directly in the GUI **Command** entry field or in any serial terminal connected to the ZedBoard.

### Core Commands

| Command | Description |
|---------|-------------|
| `HELP` | Print all available commands |
| `TX` | Transmit one packet at current MCS/SNR. Updates IQ plots and Packet Data tab. |
| `RX` | Listen for one incoming packet and decode it. |
| `LOOP N` | TX→RX loopback N times. Reports per-packet BER and final PER. |
| `SWEEP` | Run BER vs SNR sweep across the configured range. Plots BER/PER curve. |
| `SNR S` | Set AWGN noise to target SNR of **S** dB (e.g. `SNR 20`) |
| `MCS M` | Select modulation/coding scheme **M** = 0–7 (see table below) |
| `CAPIQ N` | Capture **N** IQ samples (max 4096) into host buffer; emits `##IQ_BURST` + `##CAPIQ_DONE` |
| `PARAM name value` | Set a named RF parameter at runtime (see Section 10.2) |

### MCS Table (IEEE 802.11a)

| MCS | Modulation | Code Rate | Data Rate |
|-----|-----------|-----------|-----------|
| 0 | BPSK | 1/2 | 6 Mbps |
| 1 | BPSK | 3/4 | 9 Mbps |
| 2 | QPSK | 1/2 | 12 Mbps |
| 3 | QPSK | 3/4 | 18 Mbps |
| 4 | 16-QAM | 1/2 | 24 Mbps |
| 5 | 16-QAM | 3/4 | 36 Mbps |
| 6 | 64-QAM | 2/3 | 48 Mbps |
| 7 | 64-QAM | 3/4 | 54 Mbps |

### Runtime RF Parameters (`PARAM` command)

```
PARAM lo_freq   2400000000     # RX/TX LO frequency in Hz (70 MHz – 6 GHz)
PARAM fs        20000000       # Sampling rate in Hz (up to 56 MSPS)
PARAM tx_atten  10000          # TX attenuation in milli-dB (0 = max power)
PARAM n_pkts    100            # Packets per LOOP or SWEEP point
```

### Typical Test Session

```
MCS 0           # Start with BPSK 1/2 (most robust)
SNR 30          # High SNR — expect near-zero BER
LOOP 100        # Send 100 packets, check BER in log and Packet Data tab
SNR 10          # Reduce SNR — expect more errors
LOOP 100        # Repeat
SWEEP           # Full BER vs SNR curve (uses SNR range set in GUI fields)
CAPIQ 256       # Capture 256 IQ samples for detailed waveform inspection
```

## 11. Understanding the GUI Tabs

### Tab 1 — BER/PER vs SNR

- Updates live after every `##PKT` message.
- After `SWEEP` completes, displays the full BER and PER curve on a log-linear scale.
- Y-axis: BER or PER (log scale). X-axis: SNR (dB, linear).

### Tab 2 — IQ View

Four subplots updated after every `##IQ_BURST` message:

| Subplot | Shows |
|---------|-------|
| Top-left | TX constellation (I vs Q scatter) |
| Top-right | RX constellation (I vs Q scatter, shows noise) |
| Bottom-left | TX time-domain (I and Q amplitude vs sample index) |
| Bottom-right | RX time-domain (I and Q amplitude vs sample index) |

Samples accumulate in a rolling 16,384-point buffer for continuous streaming. Auto-emits 32 samples per TX command; use `CAPIQ N` for more.

### Tab 3 — Frequency Domain

- Welch's averaged PSD using 64-point Hann-windowed FFT.
- Frequency axis: ±10 MHz (calibrated for 20 MSPS).
- Green dashed lines at ±8.125 MHz mark the 802.11a signal band edges.
- Yellow dotted line at DC marks the null sub-carrier.
- At 64-point FFT and 20 MSPS, each bin = **312.5 kHz** = one OFDM sub-carrier slot.

### Tab 4 — Packet Data

- **Top section:** TX reference bytes from `##TX_REF` (what was sent).
- **Bottom section:** Received packet log from `##PKT_DATA`.
  - **Green** byte = received correctly.
  - **Red** byte = error vs TX reference.
- Scrollable — retains all packets in the current session.
- Use **Clear** button to reset between tests.

## 12. Serial Protocol Reference

All machine-readable messages from the firmware start with `##`. Human-readable debug output does not have this prefix and is shown only in the GUI log panel.

| Message | Format | Description |
|---------|--------|-------------|
| `##PKT` | `pkt=N fcs=0/1 hdr=0/1 ber=F snr=S mcs=M` | Per-packet result. Updates BER tab. |
| `##PKT_DATA` | `pkt=N fcs=0/1 hdr=0/1 hex=B0 B1 ...` | Raw decoded bytes. Updates Packet Data tab. |
| `##TX_REF` | `hex=B0 B1 ...` | Transmitted reference bytes. Sets Packet Data top panel. |
| `##IQ_BURST` | `is_tx=0/1 n=N data=I0,Q0,I1,Q1,...` | IQ sample burst. Updates IQ View and FFT tabs. |
| `##CAPIQ_DONE` | `n=N` | Signals end of a `CAPIQ` capture. |
| `##BER` | `snr=S mcs=M ber=F per=F` | One sweep data point. Updates BER/PER plot. |
| `##DONE` | *(no payload)* | Command completed. |

## 13. GPIO Bit-Field Reference

The ARM PS communicates with the PL exclusively through a 64-bit AXI GPIO register pair.

### `gpio_o` — PS writes to PL (control)

| Bits | Signal | Description |
|------|--------|-------------|
| 0 | `phy_tx_start` | Assert for 1 cycle to trigger TX |
| 1 | `awgn_enable` | 1 = inject AWGN noise |
| 6:2 | `awgn_scale[4:0]` | Noise amplitude scale (5-bit) |
| 7 | `iq_sel` | 0 = read TX IQ buffer, 1 = read RX IQ buffer |
| 18:7 | `iq_idx[11:0]` | 12-bit sample address (0–4095) |
| 23:19 | `mcs_index[4:0]` | Selects packet ROM and modulation |

### `gpio_i` — PL writes to PS (status/data)

| Bits | Signal | Description |
|------|--------|-------------|
| 0 | `phy_tx_done` | TX complete (level, cleared by PS) |
| 1 | `rx_fcs_ok` | 1 = last packet FCS passed |
| 2 | `rx_pkt_hdr_valid` | 1 = SIGNAL field decoded OK |
| 3 | `rx_fcs_strobe` | Pulses at end of each received packet |
| 4 | `rx_byte_strobe` | Pulses when `rx_byte_out` is valid |
| 12:5 | `rx_byte_out[7:0]` | One decoded payload byte |
| 28:13 | `iq_data_i[15:0]` | I sample from the selected IQ capture buffer |
| 44:29 | `iq_data_q[15:0]` | Q sample from the selected IQ capture buffer |

## 14. Troubleshooting

### Vivado build fails with "IP not found: axi_ad9361"

The ADI IP library has not been built yet. Run Section 5 (`build_adi_lib.tcl`) first.

### Vivado build fails with "No such file: iq_sample_fifo.v"

You are running `vivado` from the wrong directory. Always run from inside `zed_fmcs3/`:
```bash
cd open_ofdm_phy-hw-clean-ofdm-rebuild/v2/boards/zed_fmcs3/
vivado -mode batch -source build.tcl
```

### ZedBoard UART shows nothing

- Check the USB cable is in the **UART** port (J14), not the JTAG port.
- Verify baud rate is exactly **115200**, 8N1, no flow control.
- On Linux, add yourself to the `dialout` group: `sudo usermod -aG dialout $USER` then log out/in.

### GUI shows "Port not found" or cannot connect

- Unplug and replug the USB cable.
- On Linux: `ls /dev/ttyUSB*` to find the correct port.
- On Windows: check Device Manager under "Ports (COM & LPT)".

### TX works but RX always shows FCS fail / no bytes

- Verify the **SMA loopback cable** is firmly connected (TX port → RX port on FMCOMMS3).
- Try `SNR 40` to maximise SNR (minimum AWGN noise).
- Try `MCS 0` (BPSK 1/2 — most robust modulation).
- Check the AD9361 init log on the serial console for calibration errors.

### IQ plots show flat lines / all zeros

- The IQ capture requires the **new bitstream** (the one built from this repo) with the 4096-deep Block RAM buffers. An old bitstream with 5-bit GPIO addressing will only capture 32 samples correctly.
- Confirm by running `CAPIQ 64` — if `##CAPIQ_DONE n=64` appears, the new bitstream is running.

### `##PKT_DATA` messages appear in the log but Packet Data tab stays empty

This was a known bug (fixed). The Python parser must match `PKT_DATA` **before** `PKT` in the `elif` chain. Verify `ofdm_gui.py` has `PKT_DATA` checked first (around line 1070).

### Python GUI import error: "No module named PIL.ImageTk"

```bash
pip install --upgrade Pillow
```
The system PIL package on some Linux distributions lacks `ImageTk`. The pip version fixes this.

### Vivado timing fails (negative WNS)

Run implementation a second time — timing closures sometimes differ between runs on the same design. If it consistently fails, check that `system_constr.xdc` includes the correct clock constraints for `bb_clk` and `l_clk`.

## 15. Architecture Summary

### Clock Domains

| Clock | Source | Frequency | Used by |
|-------|--------|-----------|---------|
| `bb_clk` | axi_clkgen (AD9361 ref) | ~40 MHz | OFDM TX/RX, TX IQ capture |
| `l_clk` | AD9361 RX clock | ~40 MHz | AD9361 data interface, RX IQ capture |
| `s_axi_aclk` | Zynq PS AXI | 166 MHz | AXI GPIO, control registers |
| `cpu_clk` | Zynq PS | 666 MHz | ARM Cortex-A9 |

All inter-domain signal crossings use two-flip-flop synchronisers. The 12-bit IQ index bus (`iq_idx`) is treated as a quasi-static value settled before a burst read.

### IQ Capture Buffer Sizing

| Buffer | Depth | Bits | Clock domain | Valid range |
|--------|-------|------|-------------|-------------|
| TX IQ I | 4096 | 16-bit signed | bb_clk | 0 – (packet length – 1) |
| TX IQ Q | 4096 | 16-bit signed | bb_clk | same |
| RX IQ I | 4096 | 16-bit signed | l_clk | 0 – 3499 (CAPTURE_LIMIT) |
| RX IQ Q | 4096 | 16-bit signed | l_clk | same |

Indices 3500–4095 in the RX buffer contain stale data from the previous capture.

### Full OFDM Packet Size at BPSK 1/2

A complete IEEE 802.11a packet at MCS 0 (BPSK 1/2, 100-byte PSDU) takes approximately **3120 baseband samples** at 20 MSPS. The `CAPTURE_LIMIT` in the HDL is set to **3500 samples**, which safely captures the entire packet with margin.
